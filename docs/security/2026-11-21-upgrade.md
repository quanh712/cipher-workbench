  `uv sync --locked`. FastAPI 0.165.0, Starlette 1.10.0, Pydantic 2.14.4 and
  pydantic-core 2.50.5 were resolved together. SQLAlchemy is now 2.1.9,

  dependencies, including React/React DOM 19.3.1, Playwright 1.65.1,
  jest-dom 8.0.0, jsdom 31.0.1, Prettier 3.10.1 and Vitest 5.1.1.

  satisfies it; CI and the public build continue using Node 22.
- Upgraded uv in the public Dockerfile and CI from 0.13.7 to 0.13.9.
  setup-uv now requires a known download checksum.
- Updated all seven external GitHub Actions to their latest stable releases,
  retaining full commit SHA pins. Verified configured inputs against each
  action's `action.yml` at that SHA; actionlint also passes.
- Added weekly CI checks and Dependabot version updates for npm, uv and the
  root Dockerfile. The new version-update PRs target `dev`; no automatic
  merging or deployment is configured.
- Adapted two Hill tests for pytest 9.2: patch the backing State mapping so
  undo restores `public_mode` correctly. Assertions and public resource limits

  full run verifies the correction across the suite.

## Compatibility choices

TypeScript remains **6.0.3**. The latest stable typescript-eslint 8.73.0 declares
`typescript >=4.8.4 <6.1.0`; its optional native compiler peer targets a 7.1
prerelease, rather than TypeScript 7.0.2 stable. No forced or legacy peer
resolution was used. Source: [typescript-eslint package metadata](https://registry.npmjs.org/typescript-eslint/8.73.0),
[typescript-estree package metadata](https://registry.npmjs.org/@typescript-eslint/typescript-estree/8.73.0).

Python stays on 3.12, as required by `backend/pyproject.toml`. A public candidate
image was rebuilt with `docker build --pull`; it reports Python 3.12.16 and
OpenSSL 3.0.22. This is not an OS vulnerability scan. The running local Compose
application and both Render deployments were not replaced.

Recovery Dockerfiles under `frontend/` and `backend/`, sibling legacy
repositories, and the machine's Docker/Compose installation were not changed.
